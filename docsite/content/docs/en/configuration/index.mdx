Labelgate supports three configuration modes. All options follow the same naming convention — see the [Configuration Reference](/docs/configuration/reference) for the complete list.

<Callout type="warn">
Configuration is strict: unknown keys and invalid values stop Labelgate at startup with a message naming the offending key. Keys removed in v0.3 are rejected too; see [Removed Keys](/docs/configuration/reference#removed-keys).
</Callout>

## Configuration Modes

### 1. Environment Variables Only (Recommended for Simple Setups)

No config file needed. Set environment variables with the `LABELGATE_` prefix:

```bash
LABELGATE_CLOUDFLARE_API_TOKEN=your-token
LABELGATE_CLOUDFLARE_ACCOUNT_ID=your-account-id
LABELGATE_CLOUDFLARE_TUNNEL_ID=your-tunnel-id
LABELGATE_API_TOKEN=a-long-random-string
```

This is the simplest approach and is used in the [Getting Started](/docs/getting-started) guide.

### 2. Config File

Use a config file for more complex setups (e.g., multi-credential, multi-tunnel, named agents). YAML, JSON and TOML are supported; ready-made examples live in the repository's `configs/` directory.

```yaml
# labelgate.yaml
cloudflare:
  api_token: your-cloudflare-api-token
  account_id: your-account-id
  tunnel_id: your-tunnel-id
```

The config file is located in this order:

1. The `-c` / `--config` command-line flag (`labelgate -c /path/to/labelgate.yaml`)
2. The `LABELGATE_CONFIG` environment variable
3. `./labelgate.{yaml,yml,json,toml}`
4. `/etc/labelgate/labelgate.{yaml,yml,json,toml}`

A missing file in the default search paths is fine; a missing file that you named explicitly (flag or `LABELGATE_CONFIG`) is an error.

### 3. Hybrid Mode

Combine both: use a config file for non-sensitive settings and environment variables for secrets.

**Priority: Environment Variables > Config File > Defaults**

```yaml
# labelgate.yaml - config file for non-sensitive settings
cloudflare:
  account_id: your-account-id
  tunnel_id: your-tunnel-id
```

```bash
# Secrets via environment variables (override config file values)
LABELGATE_CLOUDFLARE_API_TOKEN=your-token
LABELGATE_API_TOKEN=a-long-random-string
```

## Command Line

```
labelgate [-c|--config PATH] [--version]      run (main or agent mode, from the configuration)
labelgate [-c|--config PATH] healthcheck      container HEALTHCHECK, see below
```

| Exit code | Meaning |
|-----------|---------|
| `0` | Clean shutdown after `SIGINT`/`SIGTERM`; `healthcheck`: healthy; `--version` |
| `1` | Fatal error, invalid configuration, or `healthcheck`: unhealthy |
| `2` | Usage error (unknown flag or command) |

The configuration is read once at startup. Sending `SIGHUP` only logs a warning: restart Labelgate to apply changes. On `SIGINT`/`SIGTERM` the API and agent listener stop first, then the reconciler, then the database is closed; a second signal terminates immediately. The [healthcheck](/docs/configuration/reference#healthcheck) reads the same configuration as the daemon.
