## Format

```
labelgate.tunnel.<service_name>.<property>=<value>
```

Invalid values and unknown properties are errors; see [Strict Validation](/docs/labels#strict-validation).

## Properties

| Property | Required | Default | Description |
|----------|----------|---------|-------------|
| `hostname` | Yes | - | Public hostname for the service (normalised to lower-case) |
| `service` | Yes | - | Backend service URL: `protocol://host:port` (see [Service Protocols](#service-protocols)) |
| `tunnel` | No | default tunnel | Tunnel name (key of `cloudflare.tunnels`) or tunnel ID. Empty = `default_tunnel` / the root tunnel. An unknown tunnel is an error |
| `path` | No | - | Path regex to match (e.g., `\.(jpg\|png)$`). Must compile as a Go (RE2) regular expression, otherwise the service is dropped with `invalid path regex` |
| `credential` | No | automatic | Credential used for the tunnel's CNAME record and Access. Empty = zone match, then root credential |
| `cleanup` | No | `true` | Remove the ingress rule (and its CNAME) after the container is gone and `sync.remove_delay` has passed. Only owned rules are ever removed |
| `access` | No | - | Name of an [Access policy definition](/docs/labels/access) to apply (lowercase letters, digits and hyphens) |

## Service Protocols

The `service` scheme must be one of the following (schemes are case-insensitive). `http`, `https`, `ssh`, `rdp`, `tcp` and `udp` need a host (`scheme://host[:port]`); the port is not checked by Labelgate. `unix:` and `unix+tls:` need a socket path, and `http_status:` needs a code from 100 to 599. Anything else is rejected with `unsupported service scheme`.

| Protocol | Format | Description |
|----------|--------|-------------|
| HTTP | `http://host:port` | HTTP service |
| HTTPS | `https://host:port` | HTTPS service |
| SSH | `ssh://host:port` | SSH access |
| RDP | `rdp://host:port` | Remote Desktop |
| TCP | `tcp://host:port` | Raw TCP |
| UDP | `udp://host:port` | UDP (requires WARP) |
| Unix | `unix:/path/to/socket` | Unix socket |
| Unix + TLS | `unix+tls:/path/to/socket` | Unix socket with TLS |
| Hello World | `hello_world` | Test endpoint |
| HTTP Status | `http_status:404` | Return a fixed status code |
| Bastion | `bastion` | Browser-rendered bastion |

<Callout type="info">
For each tunnel hostname Labelgate creates a CNAME record pointing to `<tunnel-id>.cfargotunnel.com`, marked as owned like every other DNS record. Do not add a separate DNS service for the same hostname: that is a [conflict](/docs/labels#dns-and-tunnel-on-the-same-hostname).
</Callout>

<Callout type="warn">
Services reported by [agents](/docs/examples/multi-host#ssrf-guard) are checked by an SSRF guard: `localhost` and `*.localhost`, loopback, link-local, unspecified and multicast IP addresses, `unix:` / `unix+tls:` sockets and `bastion` are rejected, and the tunnel must be on the agent's allow-list.
</Callout>

## Ownership of Ingress Rules

Labelgate only manages the ingress rules it created, identified by (tunnel, hostname, path). Rules you created by hand, the catch-all rule, the global `originRequest` and `warp-routing` settings are preserved untouched. If you label a hostname that already has a manual rule, the service gets `conflict: existing record not owned by labelgate` and the manual rule is left alone. See [Ownership & Conflicts](/docs/ownership#coexisting-with-manually-managed-tunnel-ingress).

## Origin Request Configuration

Fine-tune the connection between cloudflared and your origin service. Duration values accept `30s`-style durations or plain seconds (`30`) and must be whole, non-negative seconds (`1500ms` is an error). `keep_alive_connections` is an integer from 0 to 1048576, the booleans follow the same forms as the DNS `proxied` label, and an unknown setting (`origin.foo`) is reported as an unknown property. An unset or empty setting is removed from the rule; settings Labelgate does not model are preserved.

### Connection Settings

```yaml
labels:
  labelgate.tunnel.web.origin.connect_timeout: "30s"
  labelgate.tunnel.web.origin.tls_timeout: "10s"
  labelgate.tunnel.web.origin.tcp_keepalive: "30s"
  labelgate.tunnel.web.origin.keep_alive_connections: "100"
  labelgate.tunnel.web.origin.keep_alive_timeout: "90s"
```

### TLS Settings

```yaml
labels:
  labelgate.tunnel.web.origin.no_tls_verify: "false"
  labelgate.tunnel.web.origin.origin_server_name: ""
  labelgate.tunnel.web.origin.ca_pool: ""
```

### HTTP Settings

```yaml
labels:
  labelgate.tunnel.web.origin.http_host_header: ""
  labelgate.tunnel.web.origin.no_happy_eyeballs: "false"
  labelgate.tunnel.web.origin.disable_chunked_encoding: "false"
```

### Proxy Settings

```yaml
labels:
  # Empty string or "socks"
  labelgate.tunnel.web.origin.proxy_type: ""
```

## Per-container defaults

`labelgate.tunnel.default.<property>` sets defaults for `tunnel`, `credential` and `cleanup` for every tunnel service of the container (other properties in a `default` block are reported as unknown):

```yaml
labels:
  labelgate.tunnel.default.tunnel: "secondary"
  labelgate.tunnel.web.hostname: "app.example.com"
  labelgate.tunnel.web.service: "http://app:80"
  labelgate.tunnel.api.hostname: "api.example.com"
  labelgate.tunnel.api.service: "http://app:3000"
```

## Examples

### Basic web service

```yaml
services:
  webapp:
    image: nginx:alpine
    labels:
      labelgate.tunnel.web.hostname: "app.example.com"
      labelgate.tunnel.web.service: "http://webapp:80"
```

### Multiple services on one container

```yaml
services:
  app:
    image: myapp:latest
    labels:
      labelgate.tunnel.web.hostname: "www.example.com"
      labelgate.tunnel.web.service: "http://app:80"

      labelgate.tunnel.api.hostname: "api.example.com"
      labelgate.tunnel.api.service: "http://app:3000"
```

### SSH access through tunnel

```yaml
services:
  dev-server:
    image: ubuntu:latest
    labels:
      labelgate.tunnel.ssh.hostname: "ssh.example.com"
      labelgate.tunnel.ssh.service: "ssh://dev-server:22"
```

### Using a specific tunnel

```yaml
services:
  internal:
    image: internal-app:latest
    labels:
      labelgate.tunnel.app.hostname: "internal.company.io"
      labelgate.tunnel.app.service: "http://internal:8080"
      labelgate.tunnel.app.tunnel: "secondary"
      labelgate.tunnel.app.credential: "company"
```

### Path-based routing

Path rules are first-class: the identity of a rule is (tunnel, hostname, path), so several services can share a hostname with different paths. For the same hostname, more specific paths are written before less specific ones.

```yaml
services:
  static:
    image: nginx:alpine
    labels:
      labelgate.tunnel.static.hostname: "example.com"
      labelgate.tunnel.static.service: "http://static:80"
      labelgate.tunnel.static.path: "\\.(jpg|png|css|js)$"
      labelgate.tunnel.api.hostname: "example.com"
      labelgate.tunnel.api.service: "http://api:3000"
      labelgate.tunnel.api.path: "^/api/"
```
