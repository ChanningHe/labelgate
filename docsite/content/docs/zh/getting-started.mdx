title: 快速开始
description: 用 Docker Compose 运行 Labelgate，并通过 Cloudflare Tunnel 发布你的第一个应用。
---

跟着本页操作，你会从零开始，让 `https://app.example.com` 通过 Cloudflare Tunnel 对外提供服务。

你需要：

- Docker 和 Docker Compose；
- 一个托管在 Cloudflare 上的域名；
- 一个 Cloudflare Tunnel。在 [Zero Trust > Networks > Tunnels](https://one.dash.cloudflare.com/) 中创建，并记下它的 **tunnel ID** 和 **token**。

## 1. 创建 Cloudflare API token [#1-create-a-cloudflare-api-token]

在 [My Profile > API Tokens](https://dash.cloudflare.com/profile/api-tokens) 创建一个自定义 token，授予以下权限：

| 你要用的功能 | 权限 |
|--------------|------|
| 仅 DNS | `Zone:Zone:Read`、`Zone:DNS:Edit` |
| DNS + Tunnel | 以上权限 + `Account:Cloudflare Tunnel:Edit` |
| DNS + Tunnel + Access | 以上权限 + `Access: Apps and Policies:Edit` |

- **Zone Resources：** 允许 Labelgate 管理的域名，或选 "All zones"。
- **Account Resources：** tunnel 所在的账户。

**Account ID** 可以在 Cloudflare dashboard 中任意域名的概览页找到。

## 2. 创建 `.env` [#2-create-env]

```bash
LABELGATE_CLOUDFLARE_API_TOKEN=your-api-token
LABELGATE_CLOUDFLARE_ACCOUNT_ID=your-account-id
LABELGATE_CLOUDFLARE_TUNNEL_ID=your-tunnel-id

# dashboard 和 API 的登录凭据，不设置则两者都不开启
# 生成方法：openssl rand -hex 32
LABELGATE_API_TOKEN=a-long-random-string

# 给 cloudflared 用的，不是给 Labelgate 的
TUNNEL_TOKEN=your-tunnel-token
```

不要把这个文件提交到版本库。

## 3. 创建 `compose.yaml` [#create-compose]

Labelgate 以用户 `65532` 运行。启动前先执行这两条命令：

```bash
stat -c '%g' /var/run/docker.sock        # 得到下面 group_add 要填的组 ID
mkdir -p labelgate-data && sudo chown -R 65532:65532 labelgate-data
```

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add:
      - "REPLACE_WITH_GROUP_ID"   # 上面 stat 命令的输出
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./labelgate-data:/app/config
    environment:
      - LABELGATE_CLOUDFLARE_API_TOKEN
      - LABELGATE_CLOUDFLARE_ACCOUNT_ID
      - LABELGATE_CLOUDFLARE_TUNNEL_ID
      - LABELGATE_API_TOKEN
    ports:
      - "127.0.0.1:28111:28111"     # dashboard 和 API，仅本机访问

  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel run --token ${TUNNEL_TOKEN}
    networks:
      - cloudflared-network

  webapp:
    image: nginx:alpine
    container_name: webapp
    labels:
      labelgate.tunnel.web.hostname: "app.example.com"
      labelgate.tunnel.web.service: "http://webapp:80"
    networks:
      - cloudflared-network

networks:
  cloudflared-network:
    name: cloudflared-network
```

Labelgate 本身不需要加入 `cloudflared-network`，它只和 Cloudflare API 打交道。这个网络让 `cloudflared` 能通过容器名访问你的应用，不用映射端口。

## 4. 启动 [#4-start-it]

```bash
docker compose up -d
```

几秒钟内，Labelgate 会为 `app.example.com` 添加一条 tunnel 规则和一条 DNS 记录。打开 `https://app.example.com`，应该能看到 nginx 欢迎页。

想看 Labelgate 管理了哪些资源，打开 `http://localhost:28111/dashboard/`，用 `LABELGATE_API_TOKEN` 登录。想看报错，执行 `docker compose logs labelgate`。

如果 `app.example.com` 在 Cloudflare 上已经存在，Labelgate 不会覆盖它，而是显示 `conflict` 错误。参见[所有权与冲突](/zh/docs/ownership)。

<Callout type="warn">
容器被删除 30 分钟后，Labelgate 会删除它在 Cloudflare 上的资源。想保留的话，加上 `labelgate.tunnel.web.cleanup: "false"`。
</Callout>

## 其他 Compose 项目中的应用 [#apps-in-other-compose-projects]

加入同一个网络并添加标签即可：

```yaml
services:
  other-app:
    image: nginx:alpine
    container_name: other-app
    labels:
      labelgate.tunnel.other.hostname: "other.example.com"
      labelgate.tunnel.other.service: "http://other-app:80"
    networks:
      - cloudflared-network

networks:
  cloudflared-network:
    external: true
```

## 只用 DNS（不用 tunnel） [#dns-only-no-tunnel]

如果只需要 DNS 记录，就不需要 `cloudflared`，也不需要 tunnel 相关设置：

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add:
      - "REPLACE_WITH_GROUP_ID"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./labelgate-data:/app/config
    environment:
      - LABELGATE_CLOUDFLARE_API_TOKEN
      - LABELGATE_API_TOKEN

  myapp:
    image: nginx:alpine
    labels:
      labelgate.dns.web.hostname: "app.example.com"
      labelgate.dns.web.type: "A"
      labelgate.dns.web.target: "203.0.113.1"
      labelgate.dns.web.proxied: "true"
```
