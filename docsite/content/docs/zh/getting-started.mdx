## 前置要求

在开始之前，请确保您已具备：

- 已安装 **Docker** 和 Docker Compose
- 拥有至少一个域名的 **Cloudflare 账户**
- 拥有 **Cloudflare API Token**（我们将在下面创建一个）

## 创建 Cloudflare API Token

前往 [Cloudflare Dashboard > My Profile > API Tokens](https://dash.cloudflare.com/profile/api-tokens) 并创建一个具有所需权限的自定义 Token：

| 使用场景 | 所需权限 |
|----------|---------------------|
| 仅 DNS | `Zone:Read` + `DNS:Edit` |
| DNS + Tunnel | `Zone:Read` + `DNS:Edit` + `Cloudflare Tunnel:Edit` |
| DNS + Tunnel + Access | `Zone:Read` + `DNS:Edit` + `Cloudflare Tunnel:Edit` + `Access: Apps and Policies:Edit` |

对于**区域资源**，选择您希望 Labelgate 管理的特定区域（域名），或选择"所有区域"以获得完全访问权限。

对于**账户资源**（Tunnel 模式必须），选择拥有 Tunnel 的账户。

您还需要您的**账户 ID**，可以在 Cloudflare Dashboard 中任何区域的概览页面上找到。

## 快速设置

### 1. 设置环境变量

在项目目录中创建 `.env` 文件：

```bash
# Labelgate configuration
LABELGATE_CLOUDFLARE_API_TOKEN=your-cloudflare-api-token
LABELGATE_CLOUDFLARE_ACCOUNT_ID=your-account-id

# Required for Tunnel mode
LABELGATE_CLOUDFLARE_TUNNEL_ID=your-tunnel-id

# Required for the API and dashboard (without it both are disabled)
# Generate one with: openssl rand -hex 32
LABELGATE_API_TOKEN=a-long-random-string

# cloudflared tunnel token (for cloudflared daemon, not Labelgate)
# Get this from: Cloudflare Dashboard > Zero Trust > Networks > Tunnels
TUNNEL_TOKEN=your-tunnel-token
```

<Callout type="warn">
dashboard 和 HTTP API 必须设置 `LABELGATE_API_TOKEN`。如果它为空，两者都会被**禁用**（Labelgate 会继续同步，并输出一条错误日志）。请不要把 `.env` 文件提交到版本控制中。
</Callout>

<Callout type="info">
如果您还没有 Tunnel，可以在 [Cloudflare Dashboard > Zero Trust > Networks > Tunnels](https://one.dash.cloudflare.com/) 中创建一个。
</Callout>

### 2. 创建 docker-compose.yaml

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    # use command "stat -c '%g' /var/run/docker.sock" to get the group id of the docker socket
    group_add:
      - "REPLACE_WITH_GROUP_ID"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - labelgate-data:/app/config
    environment:
      - LABELGATE_CLOUDFLARE_API_TOKEN
      - LABELGATE_CLOUDFLARE_ACCOUNT_ID
      - LABELGATE_CLOUDFLARE_TUNNEL_ID
      - LABELGATE_API_TOKEN
    # Dashboard 和 API（使用 LABELGATE_API_TOKEN 认证）。
    # 这里特意只绑定到本机：对外暴露之前，请先在前面放上 TLS / VPN / Cloudflare Access。
    ports:
      - "127.0.0.1:8080:8080"

  # Only needed for Tunnel mode
  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel run --token ${TUNNEL_TOKEN}

  # Example: expose a web app through Tunnel
  webapp:
    image: nginx:alpine
    labels:
      labelgate.tunnel.web.hostname: "app.example.com"
      labelgate.tunnel.web.service: "http://webapp:80"

volumes:
  labelgate-data:
```

### 3. 启动堆栈

```bash
docker compose up -d
```

Labelgate 将：
1. 连接到 Docker 守护进程并发现正在运行的容器
2. 解析 `webapp` 上的标签
3. 添加一条 Tunnel 入口规则，将 `app.example.com` 指向 `http://webapp:80`，同时保持你手工管理的任何入口规则不变
4. 创建 CNAME 记录，将 `app.example.com` 指向 `<tunnel-id>.cfargotunnel.com`，并在记录备注中标记它属于当前 Labelgate 实例

如果 `app.example.com` 已经以一条不是 Labelgate 创建的记录或规则存在，它**不会**被接管，而是得到一个 `conflict` 错误。参见[所有权与冲突](/zh/docs/ownership)。

### 4. 验证

几秒钟后，访问 `https://app.example.com` - 您的 nginx 欢迎页面应该可以通过 Cloudflare Tunnel 访问。

您也可以查看 Labelgate 日志：

```bash
docker compose logs labelgate
```

打开 `http://localhost:8080/dashboard/`，用你的 `LABELGATE_API_TOKEN` 登录即可查看被管理的资源，也可以直接调用 API：

```bash
curl -H "Authorization: Bearer $LABELGATE_API_TOKEN" http://localhost:8080/api/overview
```

<Callout type="info">
由于 `cleanup` 默认为 `true`，Labelgate 拥有的资源会在其容器消失约 30 分钟（`sync.remove_delay`）后被删除。如需保留，请设置 `labelgate.tunnel.web.cleanup: "false"`。
</Callout>

## 仅 DNS 示例

如果您只需要 DNS 记录管理（无需隧道），则更简单：

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - labelgate-data:/app/config
    environment:
      - LABELGATE_CLOUDFLARE_API_TOKEN
      - LABELGATE_API_TOKEN

  myapp:
    image: nginx:alpine
    labels:
      labelgate.dns.web.hostname: "app.example.com"
      labelgate.dns.web.type: "A"
      labelgate.dns.web.target: "203.0.113.1"
      labelgate.dns.web.proxied: "true"

volumes:
  labelgate-data:
```
