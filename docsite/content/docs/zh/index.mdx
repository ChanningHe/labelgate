---
title: 关于 Labelgate
description: 用 Docker 容器标签管理 Cloudflare DNS、Tunnel 和 Access。
---

Labelgate 监视你的 Docker 容器，并替它们配置好 Cloudflare。你给容器加上标签，Labelgate 就会创建对应的 DNS 记录、tunnel 路由或 Access 规则。容器没了，Labelgate 会负责清理。

```yaml
services:
  webapp:
    image: nginx
    labels:
      labelgate.tunnel.web.hostname: "app.example.com"
      labelgate.tunnel.web.service: "http://webapp:80"
```

从[快速开始](/zh/docs/getting-started)入手。

## 能管理什么 [#what-it-manages]

| 标签类型 | 得到什么 | 例子 |
|----------|----------|------|
| `dns` | DNS 记录（A、AAAA、CNAME、TXT、MX、SRV、CAA） | 把 `api.example.com` 指向你的服务器 |
| `tunnel` | Cloudflare Tunnel 路由 | 不开端口也能发布 `app.example.com` |
| `access` | Zero Trust Access 应用和策略 | 只允许 `alice@example.com` 访问 `admin.example.com` |

所有标签格式都一样：

```
labelgate.<type>.<name>.<property>=<value>
```

`<name>` 是你自己起的短名字，比如 `web` 或 `api`，用来把同一个服务的标签归在一起。参见 [Label 参考](/zh/docs/labels)。

## 工作方式 [#how-it-works]

- Labelgate 通过本机的 Docker socket 读取标签。其他 Docker 主机可以运行一个轻量的 [agent](/zh/docs/examples/multi-host)，把标签发给 main 实例。
- 容器一启动或停止，它就立即应用变更，并且每 5 分钟全面检查一次。
- 它只修改或删除自己创建的 Cloudflare 资源，你手工创建的记录一律不碰。参见[所有权与冲突](/zh/docs/ownership)。
- 自带 dashboard，可以查看它管理的资源和报错。
