---
title: Access 标签
description: 用标签在主机名前加一道 Cloudflare Zero Trust Access 登录。
---

Access 标签会在主机名前加一道 Cloudflare Access 登录。分两步：先定义策略，再在 tunnel 或 DNS 标签里引用它。

```yaml
services:
  admin:
    image: nginx:alpine
    labels:
      # 1. 定义一个名为 "team" 的策略
      labelgate.access.team.policy.include.emails: "alice@example.com,bob@example.com"
      # 2. 引用它
      labelgate.tunnel.admin.hostname: "admin.example.com"
      labelgate.tunnel.admin.service: "http://admin:80"
      labelgate.tunnel.admin.access: "team"
```

现在只有 Alice 和 Bob 通过 Cloudflare Access 登录后才能打开 `admin.example.com`。

## 策略标签 [#policy-properties]

标签格式都是 `labelgate.access.<name>.<property>`。`<name>` 就是策略名，在 `access: "<name>"` 中引用。它遵循[名字规则](/zh/docs/labels#service-names)。

| 属性 | 必填 | 默认值 | 示例 | 含义 |
|------|------|--------|------|------|
| `policy.include.<selector>` | `allow` 和 `block` 必填 | - | `policy.include.emails` | 策略作用于谁。满足任意一条即可。 |
| `policy.require.<selector>` | 否 | - | `policy.require.country` | 还必须同时满足这里的所有条件。 |
| `policy.exclude.<selector>` | 否 | - | `policy.exclude.emails` | 永远不作用于这些人。 |
| `policy.decision` | 否 | `allow` | `bypass` | 怎么处理。参见[决策](#decisions)。 |
| `policy.name` | 否 | 应用名 | `Team only` | 在 Cloudflare 中显示的策略名。 |
| `app_name` | 否 | `labelgate-<name>` | `Admin panel` | 在 Cloudflare 中显示的 Access 应用名。 |
| `session_duration` | 否 | `24h` | `12h` | 登录有效期。用 `m` 或 `h`（`30m`、`720h`），不支持 `7d`。 |

### 决策 [#decisions]

| `policy.decision` | 含义 |
|-------------------|------|
| `allow` | 匹配的用户登录后可以访问。需要 `include` 规则。 |
| `block` | 拦截匹配的用户。需要 `include` 规则。 |
| `bypass` | 匹配的请求无需登录即可访问。 |
| `service_auth` | 给机器用：凭 service token 或客户端证书访问，无需登录。 |

### 选择器 [#rule-selectors]

多个值用逗号分隔。

| 选择器 | 值 | 示例 |
|--------|----|------|
| `emails` | 邮箱地址 | `alice@example.com,bob@example.com` |
| `emails_ending_in` | 邮箱域名 | `example.com` |
| `ip_ranges` | IP 地址或 CIDR 网段 | `203.0.113.0/24,198.51.100.7` |
| `country` | 国家代码 | `US,GB` |
| `everyone` | 无需值（写 `""`） | `""` |
| `service_token` | Service token ID | `<token-id>` |
| `access_groups` | Access 组 ID | `<group-id>` |
| `certificate` | 无需值（写 `""`）；任何有效的客户端证书 | `""` |
| `login_methods` | 登录方式（身份提供商）ID | `<idp-id>` |

## 常用示例 [#examples]

### 所有公司邮箱

```yaml
labels:
  labelgate.access.staff.policy.include.emails_ending_in: "example.com"
  labelgate.tunnel.wiki.hostname: "wiki.example.com"
  labelgate.tunnel.wiki.service: "http://wiki:80"
  labelgate.tunnel.wiki.access: "staff"
```

### 仅限办公网络

```yaml
labels:
  labelgate.access.office.policy.include.ip_ranges: "203.0.113.0/24"
  labelgate.tunnel.intranet.hostname: "intranet.example.com"
  labelgate.tunnel.intranet.service: "http://intranet:80"
  labelgate.tunnel.intranet.access: "office"
```

### 公开访问，无需登录

```yaml
labels:
  labelgate.access.public.policy.decision: "bypass"
  labelgate.access.public.policy.include.everyone: ""
  labelgate.tunnel.docs.hostname: "docs.example.com"
  labelgate.tunnel.docs.service: "http://docs:80"
  labelgate.tunnel.docs.access: "public"
```

### 机器凭 service token 访问

```yaml
labels:
  labelgate.access.machine.policy.decision: "service_auth"
  labelgate.access.machine.policy.include.service_token: "<token-id>"
  labelgate.tunnel.api.hostname: "api.example.com"
  labelgate.tunnel.api.service: "http://api:8080"
  labelgate.tunnel.api.access: "machine"
```

### 公司邮箱、仅限美国、排除外包人员

```yaml
labels:
  labelgate.access.secure.policy.include.emails_ending_in: "example.com"
  labelgate.access.secure.policy.require.country: "US"
  labelgate.access.secure.policy.exclude.emails: "contractor@example.com"
  # 引用方式：labelgate.tunnel.<name>.access: "secure"
```

### 多个主机名共用一个策略

策略只需定义一次，同一主机上的任何容器都能引用。

```yaml
services:
  policies:
    image: busybox
    command: sleep infinity    # 必须保持运行
    labels:
      labelgate.access.team.policy.include.emails_ending_in: "example.com"

  app:
    image: nginx:alpine
    labels:
      labelgate.tunnel.app.hostname: "app.example.com"
      labelgate.tunnel.app.service: "http://app:80"
      labelgate.tunnel.app.access: "team"
```

## 注意事项

- **策略放在哪里。** 放在同一个容器里，或同一主机上任何正在运行的容器里。在 [agent](/zh/docs/examples/multi-host) 上，只看该 agent 上的容器。
- **同名策略。** 容器自身的策略优先。否则，如果另外两个容器定义了同名但内容不同的策略，会报 `ambiguous access policy definition`，请改掉其中一个的名字。
- **清理。** 策略没有 `cleanup` 标签，它的 Access 应用跟随引用它的 tunnel 或 DNS 标签一起清理或保留。
- **修改会生效。** 修改标签（比如删掉一个邮箱）后，下次同步时 Cloudflare 上也会更新。
- **不动已有应用。** 如果 Cloudflare 上已有不是 Labelgate 创建的、针对该主机名的 Access 应用，会报 `conflict: existing record not owned by labelgate`。参见[所有权与冲突](/zh/docs/ownership)。
