---
title: Tunnel 标签
description: 用标签通过 Cloudflare Tunnel 发布容器服务。
---

两个标签就能通过 tunnel 发布一个服务：

```yaml
services:
  web:
    image: nginx:alpine
    labels:
      labelgate.tunnel.web.hostname: "app.example.com"
      labelgate.tunnel.web.service: "http://web:80"
```

Labelgate 会在 tunnel 上添加一条路由 `app.example.com → http://web:80`，并创建一条把 `app.example.com` 指向该 tunnel 的 DNS 记录。

使用前请确认：

- 已配置 tunnel：`cloudflare.tunnel_id`（`LABELGATE_CLOUDFLARE_TUNNEL_ID`）以及 `cloudflare.account_id`。
- 该 tunnel 的 `cloudflared` 正在运行，参见 [cloudflared 配置](/zh/docs/examples/cloudflared)。
- `cloudflared` 能访问 `service` 地址。连接服务的是 cloudflared，不是 Labelgate。对 `http://web:80` 来说，要把 `web` 和 cloudflared 放在同一个 Docker 网络里。

## 标签 [#properties]

标签格式都是 `labelgate.tunnel.<name>.<property>`。`<name>` 由你自己定，参见[名字部分](/zh/docs/labels#service-names)。

| 属性 | 必填 | 默认值 | 示例 | 含义 |
|------|------|--------|------|------|
| `hostname` | 是 | - | `app.example.com` | 公开访问的主机名。 |
| `service` | 是 | - | `http://web:80` | cloudflared 把流量转发到哪里。参见[服务格式](#service-protocols)。 |
| `path` | 否 | - | `^/api/` | 只匹配路径符合该正则表达式的请求。 |
| `tunnel` | 否 | 默认 tunnel | `secondary` | `cloudflare.tunnels` 中的名字，或 tunnel ID。默认用 `default_tunnel`，未设置时用 `cloudflare.tunnel_id`。 |
| `cleanup` | 否 | `true` | `false` | 容器删除后是否删除路由及其 DNS 记录。`false` 表示保留。 |
| `credential` | 否 | 自动 | `company` | 主机名的 DNS 记录和 Access 应用使用哪个 [API token](/zh/docs/configuration/reference#multi-credential-setup)。 |
| `access` | 否 | - | `team` | 在主机名前加一道 [Access 策略](/zh/docs/labels/access)。 |
| `origin.<setting>` | 否 | - | `origin.no_tls_verify: "true"` | 调整到服务的连接。参见[源站设置](#origin-request-configuration)。 |

## 服务格式 [#service-protocols]

| `service` | 用途 |
|-----------|------|
| `http://host:port`、`https://host:port` | Web 应用 |
| `ssh://host:port`、`rdp://host:port` | SSH、远程桌面 |
| `tcp://host:port`、`udp://host:port` | 其他 TCP 或 UDP 服务 |
| `unix:/path/to.sock`、`unix+tls:/path/to.sock` | cloudflared 所在主机上的 Unix socket |
| `http_status:404` | 固定返回某个 HTTP 状态码（100-599） |
| `hello_world` | Cloudflare 的测试页面 |
| `bastion` | Cloudflare bastion 模式 |

## 源站设置 [#origin-request-configuration]

写法是 `labelgate.tunnel.<name>.origin.<setting>`。不写某项就使用 cloudflared 的默认值。

| 设置 | 示例 | 含义 |
|------|------|------|
| `connect_timeout` | `30s` | 连接服务的超时时间。 |
| `tls_timeout` | `10s` | 与服务 TLS 握手的超时时间。 |
| `tcp_keepalive` | `30s` | TCP keep-alive 间隔。 |
| `keep_alive_connections` | `100` | 最多保留的空闲连接数。 |
| `keep_alive_timeout` | `90s` | 空闲连接保留多久。 |
| `no_tls_verify` | `true` | 接受服务的任何证书（如自签名证书）。 |
| `origin_server_name` | `app.internal` | 服务证书上应有的主机名。 |
| `ca_pool` | `/certs/ca.pem` | cloudflared 校验服务证书用的 CA 文件。 |
| `http_host_header` | `app.internal` | 发给服务的 `Host` 头。 |
| `no_happy_eyeballs` | `true` | 关闭 Happy Eyeballs（IPv4/IPv6 回退）。 |
| `disable_chunked_encoding` | `true` | 关闭分块传输编码。 |
| `proxy_type` | `socks` | `socks`，或留空表示不用代理。 |

时间必须是整秒：`30s`、`2m`，或直接写 `30`。

## 常用示例 [#examples]

### 一个容器多条路由

```yaml
labels:
  labelgate.tunnel.web.hostname: "www.example.com"
  labelgate.tunnel.web.service: "http://app:80"
  labelgate.tunnel.api.hostname: "api.example.com"
  labelgate.tunnel.api.service: "http://app:3000"
```

### 同一主机名按路径分流

```yaml
labels:
  labelgate.tunnel.api.hostname: "example.com"
  labelgate.tunnel.api.service: "http://api:3000"
  labelgate.tunnel.api.path: "^/api/"
  labelgate.tunnel.site.hostname: "example.com"
  labelgate.tunnel.site.service: "http://site:80"
```

`/api/...` 的请求转发到 `api`，其余请求转发到 `site`。

### 使用自签名证书的 HTTPS 服务

```yaml
labels:
  labelgate.tunnel.nas.hostname: "nas.example.com"
  labelgate.tunnel.nas.service: "https://nas:5001"
  labelgate.tunnel.nas.origin.no_tls_verify: "true"
```

### SSH

```yaml
labels:
  labelgate.tunnel.ssh.hostname: "ssh.example.com"
  labelgate.tunnel.ssh.service: "ssh://dev-server:22"
```

### 使用另一个 tunnel

```yaml
labels:
  labelgate.tunnel.app.hostname: "internal.example.com"
  labelgate.tunnel.app.service: "http://internal:8080"
  labelgate.tunnel.app.tunnel: "secondary"   # cloudflare.tunnels 中的名字
```

### 容器级默认值 [#per-container-defaults]

`labelgate.tunnel.default.<property>` 为同一容器里的所有 tunnel 名字设置默认值。可用的属性：`tunnel`、`credential`、`cleanup`。

```yaml
labels:
  labelgate.tunnel.default.tunnel: "secondary"
  labelgate.tunnel.web.hostname: "app.example.com"
  labelgate.tunnel.web.service: "http://app:80"
  labelgate.tunnel.api.hostname: "api.example.com"
  labelgate.tunnel.api.service: "http://app:3000"
```

## 注意事项

- 不要为 tunnel 主机名再加 [DNS 标签](/zh/docs/labels/dns)。Tunnel 会自己创建 DNS 记录，再加一条就是[冲突](/zh/docs/labels#dns-and-tunnel-on-the-same-hostname)。
- 你在 Cloudflare 上手动添加的路由会被保留。如果已有路由用了相同的主机名和路径，你的标签会报 `conflict: existing record not owned by labelgate`。参见[所有权与冲突](/zh/docs/ownership)。
- 出于安全考虑，[agent](/zh/docs/examples/multi-host) 上的容器有限制：`service` 只能是 `http`、`https`、`tcp`、`ssh` 或 `rdp`（以及 `hello_world`、`http_status:`）；主机部分必须是公网或内网 IP 地址，或者已在 main 实例上该 agent 的 `services` 列表中放行。回环地址、Unix socket、`udp` 和 `bastion` 一律拒绝。
