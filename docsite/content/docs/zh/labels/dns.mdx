## Format

```
labelgate.dns.<service_name>.<property>=<value>
```

非法的值和未知的属性都会报错，参见[严格校验](/zh/docs/labels#strict-validation)。

## Properties

| 属性 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `hostname` | 是 | - | DNS 记录的完整域名（会规范化为小写） |
| `type` | 否 | `A` | 记录类型：`A`、`AAAA`、`CNAME`、`TXT`、`MX`、`SRV`、`CAA`（不区分大小写） |
| `target` | `A`/`AAAA`：否；其他类型：是 | `A`/`AAAA` 为 `auto` | 记录值。`auto` = 检测公网 IP，`container` = 容器 IP（两者都只适用于 `A` 和 `AAAA`），也可以是字面值。`CNAME`、`MX`、`SRV`、`TXT`、`CAA` 没有默认值，缺失时报 `target is required for <type> records` |
| `proxied` | 否 | `true` | 启用 Cloudflare 代理（橙色云朵）。仅对 `A`、`AAAA`、`CNAME` 有效，其他类型永远不代理。接受 `true`/`false`、`1`/`0`、`yes`/`no`、`on`/`off`（不区分大小写），其他值会报错 |
| `ttl` | 否 | 自动 | TTL（秒），范围 0-86400。省略、`0` 或 `1` 表示自动。启用代理时始终为自动 |
| `credential` | 否 | 自动 | 凭据名称。为空表示先按 zone 匹配，再用根凭据 |
| `cleanup` | 否 | `true` | 容器消失且超过 `sync.remove_delay` 后删除记录。只会删除 Labelgate 自己拥有的记录 |
| `comment` | 否 | - | 追加在所有权标记**之后**的备注文字（整条备注会按 Cloudflare 的 100 字符上限截断） |
| `priority` | 否 | `0` | `MX` 和 `SRV` 的优先级（0-65535） |
| `weight` | 否 | `0` | `SRV` 的权重（0-65535） |
| `port` | 否 | `0` | `SRV` 的端口（0-65535） |
| `flags` | 否 | `0` | `CAA` 的 flags（0-255） |
| `tag` | 否 | `issue` | `CAA` 的 tag：`issue`、`issuewild`、`iodef` |
| `access` | 否 | - | 要应用的 [Access 策略定义](/zh/docs/labels/access)名称（小写字母、数字和连字符）。没有任何定义提供该名称时，服务会被拒绝，原因为 `access policy definition "<name>" not found` |

<Callout type="info">
`priority` **不做强制校验**：`MX` 或 `SRV` 记录省略它时，值为 `0`。只要这个值有意义，就请显式设置（MX 例如 `10`、`20`……）。`weight`、`port`、`flags` 和 `tag` 只对上表列出的记录类型生效。
</Callout>

## 所有权与清理

Labelgate 创建的每条记录都会写入备注 `labelgate:<instance_id>`，`comment` 标签的内容会追加在其后（`labelgate:a1b2c3d4 your text`）。只有带这个标记的记录才会被更新或删除。如果已经存在名称和类型相同、但没有这个标记的记录，该服务会报 `conflict: existing record not owned by labelgate`；Labelgate 绝不会接管已有的记录。参见[所有权与冲突](/zh/docs/ownership)。

`cleanup` 默认为 **`true`**：容器停止后，记录会在 `sync.remove_delay`（默认 30 分钟）之后被删除。设置 `cleanup: "false"` 则在容器消失后仍把记录保留在 Cloudflare 上。

## Record Types

### A / AAAA 记录

将主机名指向一个 IP 地址。

```yaml
labels:
  labelgate.dns.web.hostname: "app.example.com"
  labelgate.dns.web.type: "A"
  labelgate.dns.web.target: "203.0.113.1"
  labelgate.dns.web.proxied: "true"
```

**特殊的 `target` 值：**
- `auto` - 自动检测主机的公网 IP 地址（`A` 用 IPv4，`AAAA` 用 IPv6；对于 agent 上的容器，使用该 agent 的公网 IP）
- `container` - 使用容器的 IP 地址：`A` 取 IPv4 地址，`AAAA` 取全局 IPv6 地址，均来自按名称排序后第一个具有该地址的网络
- 任何合法的 IPv4（`A`）或 IPv6（`AAAA`）地址。地址族不匹配会报错。

如果 `auto` 或 `container` 无法解析（没有对应地址族的公网 IP，或容器没有该地址族的地址），服务会进入错误状态，并在每个周期重试。同一主机名的 `A`（或 `AAAA`）记录只能由一个服务拥有，因此无法通过多个服务实现 DNS 轮询。

### CNAME 记录

创建指向另一个主机名的别名。

```yaml
labels:
  labelgate.dns.www.hostname: "www.example.com"
  labelgate.dns.www.type: "CNAME"
  labelgate.dns.www.target: "example.com"
```

目标会像主机名一样被规范化（小写、去掉末尾的点），并且必须是合法的主机名；`MX` 和 `SRV` 的目标遵循同样的规则，而 `TXT` 和 `CAA` 的值则原样保留。一个主机名只能有一条 CNAME，并且不能与其他记录共存。出现冲突时会被如实报告，而不会被绕过。

### TXT 记录

添加文本记录（SPF、DKIM、验证等）。TXT 记录从不启用代理。

```yaml
labels:
  labelgate.dns.spf.hostname: "example.com"
  labelgate.dns.spf.type: "TXT"
  labelgate.dns.spf.target: "v=spf1 include:_spf.google.com ~all"
```

### MX 记录

配置邮件交换记录。`priority` 默认为 `0`，建议显式设置。

```yaml
labels:
  labelgate.dns.mail.hostname: "example.com"
  labelgate.dns.mail.type: "MX"
  labelgate.dns.mail.target: "mail.provider.com"
  labelgate.dns.mail.priority: "10"
```

同一主机名的多条 MX 记录是彼此独立的服务；记录的标识包含优先级和目标。

### SRV 记录

服务定位记录。请设置 `priority`、`weight` 和 `port`（默认都是 `0`）。

```yaml
labels:
  labelgate.dns.xmpp.hostname: "_xmpp._tcp.example.com"
  labelgate.dns.xmpp.type: "SRV"
  labelgate.dns.xmpp.target: "xmpp.example.com"
  labelgate.dns.xmpp.priority: "10"
  labelgate.dns.xmpp.weight: "5"
  labelgate.dns.xmpp.port: "5222"
```

### CAA 记录

证书颁发机构授权记录。`target` 是记录值（CA 域名，或 `iodef` 的 URL）。

```yaml
labels:
  labelgate.dns.caa.hostname: "example.com"
  labelgate.dns.caa.type: "CAA"
  labelgate.dns.caa.target: "letsencrypt.org"
  labelgate.dns.caa.flags: "0"
  labelgate.dns.caa.tag: "issue"   # issue（默认）、issuewild、iodef
```

## Examples

### 一个容器创建多条 DNS 记录

```yaml
services:
  myapp:
    image: myapp:1.0
    labels:
      labelgate.dns.root.hostname: "example.com"
      labelgate.dns.root.type: "A"
      labelgate.dns.root.target: "auto"

      labelgate.dns.www.hostname: "www.example.com"
      labelgate.dns.www.type: "CNAME"
      labelgate.dns.www.target: "example.com"

      labelgate.dns.mail.hostname: "example.com"
      labelgate.dns.mail.type: "MX"
      labelgate.dns.mail.target: "mail.example.com"
      labelgate.dns.mail.priority: "10"
```

### 容器消失后仍保留记录

```yaml
services:
  myapp:
    image: myapp:1.0
    labels:
      labelgate.dns.app.hostname: "app.example.com"
      labelgate.dns.app.target: "auto"
      labelgate.dns.app.cleanup: "false"
```

### 临时环境（默认清理）

```yaml
services:
  preview:
    image: preview:1.0
    labels:
      labelgate.dns.preview.hostname: "preview.example.com"
      labelgate.dns.preview.target: "auto"
      # cleanup 默认为 "true"：容器停止 30 分钟
      # （sync.remove_delay）后，记录会被删除
```

### 容器级默认值 [#per-container-defaults]

`labelgate.dns.default.<property>` 可以为该容器的所有 DNS 服务设置 `type`、`target`、`proxied`、`ttl`、`credential` 和 `cleanup` 的默认值。`default` 块中的其他属性会被报告为未知属性，非法的值会使该容器的所有 DNS 服务被跳过：

```yaml
labels:
  labelgate.dns.default.proxied: "false"
  labelgate.dns.a.hostname: "a.example.com"
  labelgate.dns.b.hostname: "b.example.com"
```
