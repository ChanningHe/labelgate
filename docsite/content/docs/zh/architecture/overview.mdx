一套 Labelgate 部署包含一个 **main 实例**，以及可选的、运行在其他 Docker 主机上的 **agent**。只有 main 实例会和 Cloudflare 打交道。

```
 主机 A（main）                     主机 B（agent）
┌──────────────────────────┐       ┌───────────────────────┐
│ 带标签的容器             │       │ 带标签的容器          │
│          │               │       │          │            │
│          ▼               │  /ws  │          ▼            │
│ Labelgate main  ◄────────┼───────┼── Labelgate agent     │
│  - dashboard + API :8080 │       └───────────────────────┘
│  - 数据库                │
└──────────┬───────────────┘
           │ Cloudflare API
           ▼
     Cloudflare：DNS、Tunnel 路由、Access
           ▲
           │ tunnel 流量
     cloudflared（任意主机）
```

## 各部分运行在哪里 [#what-runs-where]

| 组件 | 运行位置 | 作用 |
|------|----------|------|
| Labelgate main | 一台主机 | 读取标签、修改 Cloudflare、保存数据库、提供 dashboard 和 API |
| Labelgate agent | 每台额外的 Docker 主机（可选） | 读取本机的标签和公网 IP，发送给 main。不持有 Cloudflare token |
| cloudflared | 任意能访问到你应用的主机 | Cloudflare 官方的 tunnel 客户端，负责转发流量。Labelgate 只负责配置它的路由 |

## 端口和数据 [#ports-and-data]

| 项目 | 默认值 | 配置项 |
|------|--------|--------|
| dashboard 和 API | `:8080` | `api.address`（`LABELGATE_API_ADDRESS`） |
| main 上的 agent 监听 | `:8081`，路径 `/ws` | `agent.listen`（`LABELGATE_AGENT_LISTEN`），需开启 `agent.enabled`（`LABELGATE_AGENT_ENABLED`） |
| 数据库 | `/app/config/labelgate.db` | `db.path`（`LABELGATE_DB_PATH`） |

请备份 `/app/config` 卷，里面记录了 Labelgate 创建过哪些资源（参见[所有权与冲突](/zh/docs/ownership#recovering-from-database-loss)）。

## 什么时候发生什么 [#what-happens-when]

- **容器启动：** Labelgate 在几秒内创建或更新它的 Cloudflare 资源。
- **容器停止：** 30 分钟后（`sync.remove_delay`）删除它的资源，除非容器在此之前回来，或设置了 `cleanup: "false"`。
- **每 5 分钟**（`sync.interval`）：Labelgate 全面检查一遍，修正任何偏差。
- **agent 离线：** 它的资源保留 24 小时（`sync.agent_grace`），所以重启或断网不会导致资源被删。

agent 的配置方法参见[多主机（Agent 模式）](/zh/docs/examples/multi-host)。
