---
title: cloudflared 部署
description: 在 Labelgate 旁边运行 cloudflared 连接器。
---

只要用了 `labelgate.tunnel.*` 标签，就需要这一页。Labelgate 负责把隧道路由写进 Cloudflare，真正转发流量的是 `cloudflared` 连接器，所以它也必须运行。

## 1. 创建隧道

1. 打开 [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) → **Networks** → **Tunnels** → **Create a tunnel** → **Cloudflared**。
2. 起个名字并保存。“public hostname” 这一步直接跳过，Labelgate 会自动添加。
3. 记下两个值：
   - **隧道 ID** → `LABELGATE_CLOUDFLARE_TUNNEL_ID`（给 Labelgate）；
   - 安装命令里的 **token**（`--token` 后面那一长串）→ `TUNNEL_TOKEN`（给 cloudflared）。

Labelgate 还需要 `LABELGATE_CLOUDFLARE_ACCOUNT_ID`，即隧道所属的账户。

## 2. 在 Compose 里加上 cloudflared

```yaml title="compose.yaml"
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}

  app:
    image: nginx:alpine
    labels:
      labelgate.tunnel.app.hostname: "app.example.com"
      labelgate.tunnel.app.service: "http://app:80"
```

cloudflared 会自动拿到新路由。标签变了也不用重启它。

带 `labelgate` 服务的完整文件见[单主机 → 隧道](/zh/docs/examples/single-host#tunnel)。

## 让 cloudflared 访问到你的服务

`service` 地址是由 cloudflared 自己去连接的，所以这个地址必须**在 cloudflared 容器里**能访问。

| 服务运行在… | `service` 写法 | 额外配置 |
|-------------|----------------|----------|
| 同一个 Compose 文件里 | `http://app:80`（服务名） | 无 |
| 另一个 Compose 项目里 | `http://app:80` | 两个容器加入同一个共享网络（见下） |
| 宿主机上（不在 Docker 里） | `http://host.docker.internal:8080` | 给 cloudflared 加 `extra_hosts`（见下） |

和其他 Compose 项目共享网络：

```yaml
services:
  cloudflared:
    networks: [tunnel]

networks:
  tunnel:
    name: tunnel # 其他项目这样加入：networks: { tunnel: { external: true } }
```

访问宿主机上的服务：

```yaml
services:
  cloudflared:
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

## 检查是否正常

- `docker compose logs cloudflared` 里有 `Registered tunnel connection`。
- Zero Trust 控制台里隧道状态是 **Healthy**。
- 控制台里该隧道的主机名路由列出了标签里的主机名。
- `curl -I https://app.example.com` 能拿到应用的响应。

## 常见问题

| 现象 | 解决办法 |
|------|----------|
| `502 Bad Gateway` | cloudflared 访问不到 `service`。用服务名而不是 `localhost`，并检查网络。 |
| 访问主机名出现 Cloudflare 错误 `1033` | cloudflared 没在运行，或用了别的隧道的 token。token 必须属于 `LABELGATE_CLOUDFLARE_TUNNEL_ID` 那条隧道。 |
| Labelgate 显示路由 `active`，cloudflared 却不生效 | cloudflared 用的是本地 `config.yml`（本地管理的隧道）。按上面的步骤在控制台创建隧道，并且只用 `--token` 运行 cloudflared。 |
| agent 主机上部分请求 `502` | 同一条隧道的流量会分给运行它的每台主机。每台主机用自己的隧道，见[多主机](/zh/docs/examples/multi-host#agent-tunnels)。 |
