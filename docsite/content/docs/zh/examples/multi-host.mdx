---
title: 多主机（Agent 模式）
description: 一个 main 实例，其他每台 Docker 主机各跑一个轻量 agent。
---

容器分布在**多台 Docker 主机**上时，用这一页。

- 一个 **main** 实例持有 Cloudflare token，所有改动都由它来做。
- 其他每台主机跑一个 **agent**。它只读取 Docker 标签并发给 main，不持有 Cloudflare token。

```
edge1 (agent) ──┐
                ├──> main ──> Cloudflare
edge2 (agent) ──┘
```

## 哪些配置放在哪里 [#what-goes-where]

| 配置 | Main | Agent |
|------|:----:|:-----:|
| Cloudflare token、账户、隧道（`cloudflare.*`） | ✓ | |
| Agent 监听：`agent.enabled`、`agent.listen`、`agent.tls.*` | ✓ | |
| Agent 列表及其 token 和允许列表：`agent.agents.<id>.*` | ✓ | |
| 共享 token 及其允许列表：`agent.accept_*` | ✓ | |
| Agent 模式：`mode: agent`（`LABELGATE_MODE=agent`） | | ✓ |
| 连接：`connect.*`（地址、agent ID、token、TLS） | | ✓ |
| 容器标签（`labelgate.dns.*`、`labelgate.tunnel.*` 等） | ✓ | ✓ |

**所有允许列表都配置在 main 上**。写在 agent 上不起任何作用。

## 示例：agent 连接 main [#outbound-mode-example]

最常用的方式，agent 在 NAT 后面也能用。示例中的 agent 叫 `edge1`，并且有自己的隧道（原因见[agent 主机的隧道](#agent-tunnels)）。

**1. 生成 token**，两台主机都要用到：

```bash
openssl rand -hex 32
```

**2. 在 main 主机上**创建 `labelgate.yaml`。Agent 只能在这个文件里配置，`agent.agents` 没有对应的环境变量。

```yaml title="labelgate.yaml（main）"
cloudflare:
  tunnels:
    edge1:                          # 第二条隧道，给 edge1 主机用
      account_id: "your-account-id"
      tunnel_id: "edge1-tunnel-id"

agent:
  enabled: true
  listen: ":28112"
  tls:
    cert: /etc/labelgate/tls/server.crt
    key: /etc/labelgate/tls/server.key
  agents:
    edge1:                          # 必须和 agent 的 LABELGATE_CONNECT_AGENT_ID 一致
      token: "PASTE_TOKEN_HERE"     # 第 1 步生成的 token
      default_tunnel: edge1
      hostnames: ["*.edge1.example.com"]
      services: ["whoami"]          # agent 的隧道服务允许使用的主机名
```

```yaml title="compose.yaml（main）"
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add: ["${DOCKER_GID}"]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - labelgate-data:/app/config
      - ./labelgate.yaml:/etc/labelgate/labelgate.yaml:ro
      - ./tls:/etc/labelgate/tls:ro
    environment:
      - LABELGATE_CLOUDFLARE_API_TOKEN
      - LABELGATE_CLOUDFLARE_ACCOUNT_ID
      - LABELGATE_CLOUDFLARE_TUNNEL_ID
      - LABELGATE_API_TOKEN
    ports:
      - "127.0.0.1:28111:28111" # 控制台
      - "28112:28112"           # agent 连接这个端口

  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}

volumes:
  labelgate-data:
```

容器以 UID 65532 运行。让它能读这些文件，同时不让其他人读：

```bash
sudo chown -R 65532 labelgate.yaml tls
sudo chmod 600 labelgate.yaml tls/server.key
```

**3. 在 agent 主机（`edge1`）上**：

```yaml title="compose.yaml（edge1）"
services:
  labelgate-agent:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add: ["${DOCKER_GID}"]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /etc/machine-id:/etc/machine-id:ro   # 稳定的 agent ID
    environment:
      - LABELGATE_MODE=agent
      - LABELGATE_CONNECT_ENDPOINT=wss://main.example.com:28112/ws
      - LABELGATE_CONNECT_AGENT_ID=edge1     # 可选，优先于 machine-id
      - LABELGATE_CONNECT_TOKEN=${AGENT_TOKEN}   # 和 main 上的 token 相同

  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}   # edge1 隧道的 token

  whoami:
    image: traefik/whoami
    labels:
      labelgate.tunnel.whoami.hostname: "whoami.edge1.example.com"
      labelgate.tunnel.whoami.service: "http://whoami:80"
```

Agent 不需要数据卷，也不需要 Cloudflare token。`target: auto` 的 DNS 标签使用的是 **agent 主机**的公网 IP。

## 示例：main 连接 agent [#inbound-mode-example]

main 能访问 agent、但 agent 访问不到 main 时用这种方式。agent 监听一个端口，由 main 主动连接。

```yaml title="labelgate.yaml（main）"
agent:
  enabled: true
  tls:
    ca: /etc/labelgate/tls/ca.pem      # 签发 agent 证书的 CA
  agents:
    edge2:
      token: "PASTE_TOKEN_HERE"
      connect_to: wss://192.168.1.12:28113/ws
      hostnames: ["*.edge2.example.com"]
```

```yaml title="compose.yaml（edge2）"
services:
  labelgate-agent:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add: ["${DOCKER_GID}"]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./tls:/certs:ro
      - /etc/machine-id:/etc/machine-id:ro   # 稳定的 agent ID
    environment:
      - LABELGATE_MODE=agent
      - LABELGATE_CONNECT_MODE=inbound
      - LABELGATE_CONNECT_LISTEN=:28113
      - LABELGATE_CONNECT_AGENT_ID=edge2     # 可选，优先于 machine-id
      - LABELGATE_CONNECT_TOKEN=${AGENT_TOKEN}
      - LABELGATE_CONNECT_TLS_CERT=/certs/server.crt
      - LABELGATE_CONNECT_TLS_KEY=/certs/server.key
    ports:
      - "28113:28113"
```

agent 的证书必须对 `connect_to` 里的主机有效。如果是 `192.168.1.12` 这样的 IP，证书的 SAN 里要包含这个 IP。

## Token 和 agent ID [#authentication]

- 所有 token 都用 `openssl rand -hex 32` 生成。token 至少 32 个字符，且至少包含 12 种不同字符。
- 同一个 token 要填两处：main 上的 `agent.agents.<id>.token`，以及 agent 上的 `connect.token`（`LABELGATE_CONNECT_TOKEN`）。
- `connect.agent_id`（`LABELGATE_CONNECT_AGENT_ID`）必须和 `agent.agents` 下的键名一致，只能用小写字母、数字、`.`、`_` 和 `-`。
- 容器重建后，agent ID 必须保持不变。请挂载 `/etc/machine-id:/etc/machine-id:ro`，或设置 `LABELGATE_CONNECT_AGENT_ID`（优先级更高）。
- 在 `agent.agents.<id>` 里命名的 agent，必须把 `LABELGATE_CONNECT_AGENT_ID` 设成同一个 `<id>`。
- 两者都没有时，agent 会用容器主机名，并在启动时打印一条警告。主机名每次重建都会变，main 会把它当成新 agent，旧 agent 的资源在 `sync.agent_grace`（`LABELGATE_SYNC_AGENT_GRACE`）之后被删除。
- Labelgate 不会展开 `labelgate.yaml` 里的 `${VAR}`，请把真实 token 直接写进文件。

## TLS [#tls]

连接地址是一个 `wss://` URL，**必须以 `/ws` 结尾**，例如 `wss://main.example.com:28112/ws`。

| | agent 连接 main | main 连接 agent |
|---|---|---|
| 证书和私钥 | main：`agent.tls.cert`、`agent.tls.key`（`LABELGATE_AGENT_TLS_CERT`、`LABELGATE_AGENT_TLS_KEY`） | agent：`connect.tls.cert`、`connect.tls.key`（`LABELGATE_CONNECT_TLS_CERT`、`LABELGATE_CONNECT_TLS_KEY`） |
| 私有 CA（不设置则用系统 CA） | agent：`connect.tls.ca`（`LABELGATE_CONNECT_TLS_CA`） | main：`agent.tls.ca`（`LABELGATE_AGENT_TLS_CA`） |

- **也可以用反向代理**：让 Caddy、Traefik 或 nginx 用你现有的证书提供 `wss://`，再把 WebSocket 转发到 28112 端口。这时 `agent.tls` 留空即可。
- **`ws://`** 也能用，但数据不加密。只在可信的局域网或 VPN 里使用。
- **`insecure_skip_verify: true`**（`connect.tls.insecure_skip_verify` / `agent.tls.insecure_skip_verify`）会关闭证书校验，只用于测试。

## 命名 agent 与共享 token [#named-vs-shared]

放行 agent 有两种方式，都配置在 **main** 上。

| | 命名 agent | 共享 token agent |
|---|---|---|
| 配置项 | `agent.agents.<id>` | `agent.accept_token`（`LABELGATE_AGENT_ACCEPT_TOKEN`） |
| Token | 每个 agent 一个 | 所有 agent 共用一个 |
| 允许列表 | `agent.agents.<id>.hostnames`、`.tunnels`、`.services`、`.default_tunnel` | `agent.accept_hostnames`、`agent.accept_tunnels`、`agent.accept_services` |
| 配置位置 | 只能写在配置文件里 | 配置文件或环境变量 |

命名 agent 更安全：每个 agent 有自己的 token 和自己的限制。共享 token 则允许任何**不在** `agent.agents` 里的 agent ID 连接。

<Callout type="warn">
**`agent.accept_*` 对命名 agent 完全不生效**。列在 `agent.agents` 下的 agent 只看它自己的 `hostnames`、`tunnels` 和 `services`，也不能用 `accept_token` 登录。

```yaml
agent:
  accept_services: ["traefik"]   # 对 edge1 无效
  agents:
    edge1:
      token: "PASTE_TOKEN_HERE"
      services: ["traefik"]      # edge1 用的是这一项
```
</Callout>

共享 token 的配置示例：

```yaml title="labelgate.yaml（main）"
agent:
  enabled: true
  # accept_token：建议用 LABELGATE_AGENT_ACCEPT_TOKEN 设置，不要写在这里
  accept_hostnames: ["*.agents.example.com"]
  accept_tunnels: [default]
  accept_services: ["traefik"]
```

`accept_*` 列表也可以用逗号分隔的环境变量设置，例如 `LABELGATE_AGENT_ACCEPT_SERVICES=traefik,web`。

## 允许列表 [#allow-lists]

允许列表限制 agent 能创建什么。违反列表的声明会被拒绝，控制台会显示原因，以及需要修改的具体配置项。被拒绝的内容不会发到 Cloudflare。

| 控制内容 | 命名 agent | 共享 token agent | 为空时 |
|----------|------------|------------------|--------|
| 可使用的主机名 | `agent.agents.<id>.hostnames` | `agent.accept_hostnames` | 任意主机名 |
| 可使用的隧道 | `agent.agents.<id>.tunnels` | `agent.accept_tunnels` | 只能用它的默认隧道 |
| 标签没写 `tunnel` 时用的隧道 | `agent.agents.<id>.default_tunnel` | （固定为全局默认隧道） | 全局默认隧道 |
| 隧道 `service` 地址中可用的主机名 | `agent.agents.<id>.services` | `agent.accept_services` | 只能用 IP 地址 |

- 主机名匹配：`*.example.com` 能匹配 `a.example.com` 和 `a.b.example.com`，但不匹配 `example.com`。
- 通配符主机名标签（`hostname: "*.example.com"`）要求列表里有完全相同的条目。
- 隧道名可以是：`default`（`cloudflare.tunnel_id` 那条隧道）、`cloudflare.tunnels` 下的键名，或隧道 ID。
- 命名 agent 总是可以使用自己的 `default_tunnel`。

## Agent 的隧道服务地址 [#ssrf-guard]

main 会检查每个来自 agent 的隧道 `service` 地址：

| `service` 指向 | 是否允许 |
|----------------|----------|
| IP 地址：`http://192.168.1.20:8080`、`http://172.18.0.5:80` | 允许，无需配置 |
| 主机名：Compose 服务名（`http://traefik:80`）、`host.docker.internal`、任意域名 | 必须写进 `services` |
| 本机类 IP：`127.0.0.1`、`169.254.x.x`、`100.64.0.0/10`、`0.0.0.0` | 必须把该 IP 或包含它的 CIDR 写进列表 |
| 其他协议（`unix:`、`bastion`）、URL 中带 `user:pass@`、`127.1` 这类 IP 简写 | 一律不允许 |

agent 可以使用 `http`、`https`、`tcp`、`ssh` 和 `rdp` 地址（以及 `hello_world` / `http_status:<code>`）。main 主机自己的容器不受此检查。

要放行主机名，就把它加进 **main** 上该 agent 的 `services`。条目可以是名字、通配模式、IP 地址或 CIDR：

```yaml title="labelgate.yaml（main）"
agent:
  agents:
    edge1:
      token: "PASTE_TOKEN_HERE"
      services:
        - traefik          # http://traefik:80
        - "*.svc.internal" # 通配模式
        - 172.20.0.0/16    # CIDR
```

## Agent 主机的隧道 [#agent-tunnels]

`service` 地址由 cloudflared 去连接。`http://whoami:80` 这种名字，只有同一台主机、同一个 Docker 网络里的 cloudflared 才能访问。而 Cloudflare 可能把一条隧道的流量发给它的任意一个 cloudflared 连接器。所以请给每台 agent 主机**单独一条隧道**：

1. 每台 agent 主机创建一条隧道（见 [cloudflared](/zh/docs/examples/cloudflared)）。
2. 在 main 上把它加到 `cloudflare.tunnels.<name>`（只能写在配置文件里），并设置 `agent.agents.<id>.default_tunnel: <name>`。
3. 在 agent 主机上用这条隧道的 token 运行 cloudflared。

[第一个示例](#outbound-mode-example)就是这样配置的。

## Agent 离线时 [#agent-grace]

- 它的 DNS 记录和隧道路由会在最后一次在线后保留 `sync.agent_grace`（`LABELGATE_SYNC_AGENT_GRACE`，默认 `24h`，最小 `5m`）。
- 超过这个时间后，再过 `sync.remove_delay`（`LABELGATE_SYNC_REMOVE_DELAY`，默认 `30m`）就会被删除，除非标签设置了 `cleanup: "false"`。
- 重启 main 不会重新计时。
- 控制台状态：`active`（已连接）、`disconnected`（离线，资源仍保留）、`removed`（资源已释放）。

## 检查是否正常

- main 日志：`docker compose logs labelgate | grep agent` 能看到 `msg="agent connected" ... agent_id=edge1`。
- agent 日志：`docker compose logs labelgate-agent` 能看到 `msg="connected to main"`。
- 控制台 → **Agents**：该 agent 是 `active`，它的资源也是 `active`；被拒绝的资源会显示原因。
- 连接地址可达：`curl https://main.example.com:28112/health` 返回 `{"status":"ok"}`。
- `curl -I https://whoami.edge1.example.com` 能拿到 agent 主机上服务的响应。

## 常见问题 [#common-problems]

| 现象 | 解决办法 |
|------|----------|
| main 日志出现 `agent handshake failed` | 两边 token 不一致，或 agent ID 不在 `agent.agents` 的键名里。重新复制 token，并核对 ID。 |
| `connect.endpoint ... has no path (did you mean .../ws?)` | 在 `LABELGATE_CONNECT_ENDPOINT` 末尾加上 `/ws`。 |
| agent 日志出现 `x509: certificate signed by unknown authority` | 把 `LABELGATE_CONNECT_TLS_CA` 设为你的 CA 文件，或改用公开签发的证书。 |
| `must be at least 32 characters` 或 `distinct characters` | 用 `openssl rand -hex 32` 重新生成 token。写在 `labelgate.yaml` 里的 `${VAR}` 不会被展开，也会触发这个错误。 |
| `service host "traefik" is a host name, which agents may only use if allow-listed` | 在 main 上把 `traefik` 加进该 agent 的 `services`。见[故障排查](/zh/docs/troubleshooting/common-issues#agent-service-host)。 |
| 已经加进 `agent.accept_services`，仍被拒绝 | 这是命名 agent，要改 `agent.agents.<id>.services`。 |
| `rejected a second connection for an agent ID that is already connected` | 两台主机用了同一个 agent ID，给每台主机设不同的 ID。 |
| `conflict: the ... is already managed by ...` | 一个主机名同一时间只属于一台主机，换一个主机名。见[所有权](/zh/docs/ownership)。 |
| agent 上的服务通过隧道访问返回 `502` | 请求被发到了另一台主机上的 cloudflared。改为[每台主机一条隧道](#agent-tunnels)。 |
| v0.2 的 agent 连不上 | main 和所有 agent 一起升级到 v0.3。见[升级](/zh/docs/upgrading)。 |
