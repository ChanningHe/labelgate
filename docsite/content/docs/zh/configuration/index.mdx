title: 配置
description: 用环境变量、配置文件或两者结合来配置 Labelgate。

Labelgate 从三个地方读取设置。同一个设置出现在多处时，排在前面的优先：

1. 环境变量（`LABELGATE_...`）
2. 配置文件（YAML、JSON 或 TOML）
3. 内置默认值

所有配置项及其环境变量见[配置参考](/zh/docs/configuration/reference)。

## 只用环境变量 [#1-environment-variables]

这是最简单的方式，单台主机足够用。

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    environment:
      LABELGATE_CLOUDFLARE_API_TOKEN: ${CF_API_TOKEN}
      LABELGATE_CLOUDFLARE_ACCOUNT_ID: ${CF_ACCOUNT_ID}
      LABELGATE_CLOUDFLARE_TUNNEL_ID: ${CF_TUNNEL_ID}
      LABELGATE_API_TOKEN: ${LABELGATE_API_TOKEN}   # openssl rand -hex 32
```

配置项对应的环境变量名：把 `.` 换成 `_`，转成大写，再加上 `LABELGATE_` 前缀。例如 `sync.remove_delay` 对应 `LABELGATE_SYNC_REMOVE_DELAY`。列表用逗号分隔：`LABELGATE_AGENT_ACCEPT_TUNNELS=default,secondary`。值为空的环境变量会被忽略。

## 配置文件 [#2-config-file]

下面这些部分没有对应的环境变量，只能写在配置文件里：

- `cloudflare.credentials`：多个 Cloudflare API token。
- `cloudflare.tunnels`：多个 tunnel。
- `agent.agents`：带独立 token 的命名 [agent](/zh/docs/examples/multi-host)。

Labelgate 使用找到的第一个文件：

1. `-c` / `--config` 指定的路径。
2. `LABELGATE_CONFIG` 中的路径。
3. 工作目录（镜像中是 `/app`）下的 `labelgate.yaml`（或 `.yml`、`.json`、`.toml`）。
4. `/etc/labelgate/labelgate.yaml`（或 `.yml`、`.json`、`.toml`）。

在 Docker 中，把文件挂载到 `/etc/labelgate/labelgate.yaml`。带注释的完整示例见 [`configs/labelgate.example.yaml`](https://github.com/channinghe/labelgate/blob/main/configs/labelgate.example.yaml)。

## 两者结合 [#3-hybrid-mode]

结构写在文件里，敏感信息用环境变量传入。环境变量会覆盖文件中的值。

配置文件不支持模板：文件里的 `${VAR}` 会原样保留，不会被替换。敏感信息请通过环境变量传入，或直接写进文件。

## 最小 main 配置 [#minimal-main-config]

`labelgate.yaml`：

```yaml
cloudflare:
  account_id: your-account-id
  tunnel_id: your-tunnel-id
# 敏感信息来自环境变量：
#   LABELGATE_CLOUDFLARE_API_TOKEN, LABELGATE_API_TOKEN
```

`docker-compose.yaml`：

```yaml
services:
  labelgate:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add:
      - "999"   # Docker socket 的属组：stat -c '%g' /var/run/docker.sock
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./labelgate.yaml:/etc/labelgate/labelgate.yaml:ro
      - ./labelgate-data:/app/config   # 数据库；sudo chown -R 65532:65532 ./labelgate-data
    environment:
      LABELGATE_CLOUDFLARE_API_TOKEN: ${CF_API_TOKEN}
      LABELGATE_API_TOKEN: ${LABELGATE_API_TOKEN}
    ports:
      - "127.0.0.1:28111:28111"   # Dashboard 和 API
```

## 最小 agent 配置 [#minimal-agent-config]

agent 运行在另一台 Docker 主机上，把那里的容器上报给 main 实例。它不需要 Cloudflare token。

在 agent 主机上：

```yaml
services:
  labelgate-agent:
    image: ghcr.io/channinghe/labelgate:v0.3
    restart: unless-stopped
    group_add:
      - "999"   # Docker socket 的属组：stat -c '%g' /var/run/docker.sock
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      LABELGATE_MODE: agent
      LABELGATE_CONNECT_ENDPOINT: wss://main.example.com:28112/ws
      LABELGATE_CONNECT_AGENT_ID: edge1      # 必须和 main 上的 agent.agents.edge1 一致
      LABELGATE_CONNECT_TOKEN: ${AGENT_TOKEN}   # openssl rand -hex 32
```

这个 agent 在 main 上登记为 `agent.agents.edge1`（见下文），所以 `LABELGATE_CONNECT_AGENT_ID` 必须是 `edge1`。只有用 `agent.accept_token` 登录的 agent 才可以不设 ID。这类 agent 请挂载 `/etc/machine-id:/etc/machine-id:ro`，这样容器重建后 ID 保持不变。

在 main 实例上，把这个 agent 以相同的 ID 和 token 加进 `labelgate.yaml`，并开放 `28112` 端口：

```yaml
agent:
  enabled: true
  tls:                          # 使用 wss:// 时需要
    cert: /app/config/tls/server.crt
    key: /app/config/tls/server.key
  agents:
    edge1:
      token: "<与 AGENT_TOKEN 相同的值>"
```

默认情况下，这个 agent 可以使用除通配符（`*.example.com`）以外的任何主机名，只能使用默认 tunnel，tunnel 的 `service` 只能写 IP 地址。如果 main 的证书来自私有 CA，请在 agent 上设置 `LABELGATE_CONNECT_TLS_CA`。白名单、inbound 模式和 TLS 选项见[多主机](/zh/docs/examples/multi-host)。

## 需要知道的事 [#rules]

- **写错就无法启动。** 未知的键和非法的值都会报错。所有问题会一次性列出，可以一次改完。
- **时长要带单位。** 写 `30s`、`5m` 或 `24h`。只写 `30` 会报错；零请写 `0s`。
- **修改后要重启。** 配置只在启动时读取一次，`SIGHUP` 不会重新加载。
- **旧配置项会报错。** v0.3 中删除的配置项会导致报错，参见[已移除的配置项](/zh/docs/configuration/reference#removed-keys)。
- **agent 只用部分设置。** 在 `mode: agent` 下，只使用 `log_*`、`docker`、`retry` 和 `connect`。

## 命令行 [#command-line]

```
labelgate [-c PATH]               运行（main 或 agent，由配置决定）
labelgate [-c PATH] healthcheck   容器健康检查
labelgate --version               输出版本号
```

配置有误时，Labelgate 会输出原因并以退出码 `1` 退出。
